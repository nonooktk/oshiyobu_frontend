# 検収

「検収して」と言われたときの手順です。前提、命令、落ちたときの表、直してよい範囲といった詳しい決まりは、`CLAUDE.md` の「8. 検収のしかた」にあります。細部は `docs/検収.md` を見てください。このスキルには、進める順番だけを書きます。

- コマンドは、Mac・Linux の bash でも Windows の PowerShell でも同じです。違うのは環境変数の入れ方だけです（`CLAUDE.md` の 8.3）。
- 画面の公開 URL と API の接続先は、文書・PR・commit に書かず、チャットにも貼りません。環境変数にだけ入れます。
- 実行してよいのは `npm run …` の命令だけです。管理者に頼む範囲（API・`src/core/`・Secrets・配備・CORS の設定・合言葉・main へのマージ）には手を出さず、そこで止まって担当者に伝えます。

## 手順

### 1. 前提を確かめる

```
node --version
npm ci
```

`node --version` の結果が、`package.json` の `engines`（22.22.2 以降の 22 系・24.15.0 以降の 24 系・26 以降）に収まっているかを見ます。範囲の外なら、そのまま進めてよいか担当者に聞きます。この場合、`verify` が「注意」を出します。

### 2. どちらで検収するか決める

どちらにするかは担当者に聞きます。すでに決まっているときは聞きません。

- **A. 手元だけで閉じる**（既定）: 管理者に値をもらわなくても実行できます。
- **B. 公開中の API・画面**: 管理者から `VITE_API_BASE` と `SWA_BASE_URL` の値をもらっているときだけ選べます。

### 3. 実行する

A の場合:

```
npm run accept -- --local-api
```

B の場合は、先に値を環境変数に入れ（`CLAUDE.md` の 8.3）、次を実行します:

```
npm run accept
```

- 初回の A は、backend の取得とビルドに 1〜2 分かかります。その間は止めずに待ちます。
- ポートが使用中だったり、ネットワークが失敗したりして途中で止まったときは、出力を全文貼って担当者に聞きます。サーバーを止める必要があるときも、止めてよいのは**自分が起動したプロセスだけ**で、PID を指定して止めます（`pkill` と `killall` は使いません）。

### 4. 結果を報告する

出力の最後にある表と「判定」を、手を加えずに次の形で報告します。

| # | 検査 | 結果（合格／不合格／飛ばした／注意） | 詳細 |
| --- | --- | --- | --- |

- 判定が「合格」でなければ、最初に「検収は完了していません」と書きます。「飛ばした」がある（終了コード 2）ときも、合格とは書きません。
- 不合格の項目は、`CLAUDE.md` の 8.5 の表を引いて、原因と直す場所を書きます。担当者が直してよい範囲なら、直し方を示します。管理者に頼む範囲なら、頼む内容（落ちた項目・出力の抜粋）を添えて担当者に伝えます。
- 直したあとは、最初の `npm run verify` からやり直します。
- 実行していない検査は、「確かめた」と書きません。

### 5. 終わりに

- 自分が起動したサーバーが残っていないか確かめます（`accept` が起動したサーバーは、自分で止まります）。
- 環境変数に値を入れていた場合は、消します（bash は `unset VITE_API_BASE SWA_BASE_URL`、PowerShell は `Remove-Item Env:VITE_API_BASE, Env:SWA_BASE_URL`）。
