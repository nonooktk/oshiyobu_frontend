# 作業のはじめ方

新しい作業を始めるときの手順です。上から順に進めます。途中で想定外のことが起きたら、そこで止まり、エラーを**全文**貼って担当者に聞きます。

## 手順

### 1. 今の状態を確認する

```
git status --short
git branch --show-current
```

- 変更が残っているときは、**ここで止まる**。残っている変更をどうするか（続きの作業か、別の作業か）を担当者に聞く。変更を捨てる操作（`git reset --hard`・`git checkout -f`・`git clean`）は使わない。
- 変更が無ければ、次へ進む。

### 2. 最新の main を取る

```
git switch main
git pull --ff-only
```

- `git pull --ff-only` が失敗したら、**ここで止まる**。エラーを全文貼って聞く。

### 3. 作業用のブランチを切る

```
git switch -c <種類>/<短い英語の名前>
```

- 種類は `feature`（機能の追加）・`fix`（不具合の修正）・`docs`（文書だけの変更）のどれか。例: `feature/add-banner`、`fix/map-label`。
- **main の上では、commit も push もしない。** 必ずブランチを切ってから作業する。

### 4. やることを日本語で書き出して、承認を待つ

次の 5 つを、担当者に読める形で書き出す。

1. 何を変えるか（1〜3 行）
2. なぜ変えるか
3. どのファイルを触るか
4. どう確かめるか（ローカルで、何をして、何が見えれば OK か）
5. 触らない範囲の確認（backend の計算・データ・API、`.env`、`.github/`、`.claude/` は変えない）

書き出したら**止まる**。「この内容で進めてよいですか」と聞く。担当者の **「OK」「進めてください」「Aで」「同意です」** のどれかが出るまで、ファイルを変えない。

### 5. 小さく直す

- 1 回の変更は、1 つの目的に絞る。大きくなりそうなら、分けることを担当者に提案する。
- 直すたびに、ローカルで確かめる。アプリの起動・テスト・ビルドのコマンドは `docs/はじめに.md` に書かれている（技術スタックが決まるまでは、未記載）。
- 「デモ用の架空データ」の表示を消さない。画面の文言に「新しい口座を開く」「口座開設」「確約」を使わない。

### 6. ローカルで確かめる

- 変えた画面と、そこから行ける画面を、目で見て確かめる。スマホの幅と PC の幅の両方で見る。
- 確かめた手順と、見えたものを、あとで PR に書けるようにメモしておく。

### 7. 区切りのところで commit する

commit の前に、**対象のファイルの一覧を担当者に見せて、確認を取る**。

```
git status --short
git add <ファイル名>
git diff --cached --stat
```

- `git add -A` と `git add .` は使わない。ファイル名を 1 つずつ指定する。
- `.env`・`*.env`・鍵のファイルが入っていないことを、一覧で確かめる。

### 8. 終わったら

作業が終わったら、`/pre-deploy-check` を呼んで、PR を出す前の確認を行う。PR の出し方と、そのあとの流れは `docs/デプロイ手順.md`。
