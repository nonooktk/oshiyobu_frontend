# docs/fan/（ファン向けの画面を引き継ぐ人へ）

ファン向けの画面（`/fan/`）は、発表（2026-11-20）に向けて、流れを作り替えました。流れと状態の骨組みは、管理者の側で作り終えています。担当者にお願いするのは、見た目の作り込みと、あとから届く素材の差し込みです。

## いまの状態

| 項目 | 状態 |
| --- | --- |
| 流れ（推しを選ぶ → 参加 → 預金でやること → SNSで広める／プランを上げる） | 動く。まとめ先のブランチ `feat/fan-flow-v2` に入っている |
| 見た目 | 最小限。作り込みは、これから |
| 特典の素材（追加の画像・5秒の動画・20秒の動画・背景の絵） | 未着。いまは仮の表示。置き場と枠は、先に作る |
| メニューの下の画面・推しのセリフ | 新しい流れの言い方にそろえてある |
| `dev` と公開中の版 | 古い流れのまま。検収が通るまで変えない |

## 文書は 5 つ

| 文書 | 中身 | 読む目安 |
| --- | --- | --- |
| `要求.md` | 統括の指示の原文と、何のための変更か | 3 分 |
| `要件.md` | 決まったこと、できること（R-番号）、だれが作るか | 5 分 |
| `仕様.md` | 画面ごとの中身、画面の目印、ストアの操作の名前、素材の置き場 | 8 分 |
| `テスト設計.md` | いまあるテスト、足すテスト、手で確かめること | 5 分 |
| `運用ルール.md` | 変えてよい所・相談する所・変えない所、ブランチと PR、素材の決まり | 5 分 |

上から順に読みます。決まりの正本は `docs/守ること.md`（G-番号）です。この階層の文書と食い違ったら、`docs/守ること.md` が勝ちます。

## 最初にやること

道具（Git・Node.js・GitHub の認証・Claude Code）が入っていなければ、先に `docs/はじめに.md` を終えます。

```
cd ~/repos/oshiyobu_frontend
git status --short
git fetch origin
git switch -c feature/fan-look --no-track origin/feat/fan-flow-v2
npm ci
npm run verify
npm run dev
```

- 切り元は `feat/fan-flow-v2` です（`dev` ではありません）。PR の向き先も `feat/fan-flow-v2` です。
- `npm run verify` の最後が `判定: 合格` なら、準備ができています。落ちたら、出力の全文を管理者へ送ります。
- `npm run dev` のあと、ブラウザで `/fan/` を開くと、新しい流れを最後まで触れます。まず 1 回、通しで触ってください。

## Claude Code への頼み方の例

順番は、計画 → 確認 → 実装です。

1. 「`docs/fan/` の 6 つの文書を読んで、内容を 5 行で言い直してください。まだファイルは変えないでください。」
2. 「`仕様.md` の 2.1（プランの一覧）の見た目を作り込みたいです。触るファイル・当たりそうな決まり（G-番号）・消してはいけない目印・確かめ方を表にして、計画を出してください。OK を出すまで変えないでください。」
3. 「OK です。計画の 1 番目だけ実装して、`npm run verify` を実行して、結果を見せてください。」
4. 「この動画を特典に足したいです。置き場・容量・`<video>` の書き方・`src/fan/art/rewards.ts` の行が、`運用ルール.md` の 4 節のとおりかを、先に確かめてください。」

## 困ったとき

- エラーは、全文を貼って聞きます。
- 決まりに当たるか分からないときは、変えずに聞きます。聞き方の雛形は、`運用ルール.md` の 5 節にあります。
