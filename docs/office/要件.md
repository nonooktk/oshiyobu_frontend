# 要件（事務所向けの画面）

`要求.md` の要求（Q-xx）を、「〜できる」の形に直します。いまの画面との差も表にします。

- 状態: 案（2026-11-14）。統括の確認が済んでいないことは、末尾の「確認事項」に並べました。
- 根拠は、コードとデータのファイル名まで書きます。確かめていないことは「未確認」と書きます。

## 1. 用語

| 語 | 意味 |
| --- | --- |
| 札 | 成立の見込みの「高」「中」「低」。見込み ÷ 必要人数で決まる（`src/core/calc/demand.ts` の `levelOf`） |
| 見込み | 払える熱いファンの人数（4 象限の右上）。推しと市で決まる（`demandOf(推し, 市).expected`） |
| 到達ライン | 費用 5 項目の合計（円）。会場の区分で初期値が決まる |
| 必要人数 | 到達ライン ÷ 通常の席の価格（切り上げ）。札の判定に使う |
| 最低人数 | 成立に要る支援者の人数。事務所と相談して決める値。初めの値は必要人数 |
| 4 象限 | 熱量（縦）× 預金額（横）で、ファンを 4 つに分けた図。いまは `Judge.tsx` の `Scatter` と `scatter.ts` |
| 境目（閾値） | 4 象限を分ける線の位置。いまは図の中央に固定（預金額 15 万円・熱量 3） |
| core | backend の計算とデータの写し（`src/core/`）。担当者は変えない（G-17） |
