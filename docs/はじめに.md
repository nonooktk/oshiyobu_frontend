# はじめに（導入から初回の起動まで）

この文書は、自分の PC でこのリポジトリを動かし、Claude Code を使って作業を始められるようになるまでの手順です。Mac と Windows の両方に対応しています。

最後までやると、次の状態になります。

1. Git・Node.js・GitHub の認証・Claude Code が使える
2. このリポジトリが、自分の PC に取得できている
3. Claude Code を起動して、最初のスキル（`/start-task`）を呼べる

初めてなら、1 時間ほど見ておいてください（目安です）。

## 0. 始める前に（Mac・Windows 共通）

### 必要なもの

| もの | 補足 |
| --- | --- |
| PC | Mac は macOS 13 以降、Windows は Windows 10（バージョン 1809）以降 |
| Claude のアカウント | Claude Code は、Pro・Max・Ultra・Team・Enterprise・Console のいずれかのアカウントで使えます。無料プランでは使えません。持っていない場合は、統括に相談してください |
| GitHub のアカウント | https://github.com で作れます |
| このリポジトリへの書き込み権限 | 統括に GitHub のユーザー名を伝えて、招待を依頼してください。招待のメールか GitHub の通知から承認します |

### コマンドの打ち方

- 灰色の枠の中のコマンドをターミナルに貼り付けて、Enter を押します。
- `<` と `>` で囲んだ部分（例: `<noreply のアドレス>`）は、自分の値に置き換えます。`<` と `>` は消します。
- コマンドがエラーになったら、止まってください。画面の表示を**全文**コピーして、統括に聞きます。

### リポジトリを置く場所

iCloud Drive・OneDrive・デスクトップ・書類の中には置かないでください。同期されるフォルダに置くと、git の管理ファイルが壊れることがあります。この文書では、ホームフォルダの下の `repos` に置きます。

## A. Mac の手順

### A-1. ターミナルを開く

`Cmd + Space` で Spotlight を開き、`Terminal` と入力して Enter を押します。

### A-2. Git を確かめる

```
git --version
```

バージョンが出れば、次へ進みます。インストールを促す画面が出たり `command not found` になったりしたら、次を実行して画面の指示に従います。終わったらもう一度 `git --version` を実行します。

```
xcode-select --install
```

### A-3. Node.js を入れる

https://nodejs.org/en/download を開き、LTS（長期サポート版）の macOS 用インストーラをダウンロードして実行します。

Homebrew の `brew install node` は、LTS ではない版（奇数の版）が入ることがあるので、この文書では使いません。

入ったことを確かめます。

```
node --version
npm --version
```

必要な Node.js のバージョンは、「C. アプリの起動・テスト・ビルド」の表のとおりです（22 LTS の 22.22.2 以降、24 LTS の 24.15.0 以降、26 以降）。入れた版が合っているか、上の `node --version` で確かめます。

### A-4. GitHub CLI を入れて、GitHub にログインする

Homebrew を使っている人は、次を実行します。

```
brew install gh
```

Homebrew を使っていない人は、https://cli.github.com/ から macOS 用のインストーラを入れます。

ログインします。

```
gh auth login
```

質問には、次のように答えます（表示は少し違うことがあります）。

1. 「What account do you want to log into?」→ `GitHub.com`
2. 「What is your preferred protocol for Git operations?」→ `HTTPS`
3. 「Authenticate Git with your GitHub credentials?」→ `Y`
4. 「How would you like to authenticate GitHub CLI?」→ `Login with a web browser`
5. 画面に出る 8 文字のコードをコピーし、Enter を押して開いたブラウザに貼り付けて承認します。

ログインできたことを確かめます。

```
gh auth status
```

### A-5. 作者の名前とメールアドレスを決める

commit には、作者の名前とメールアドレスが載ります。**このリポジトリは公開されているので、個人のメールアドレスを載せてはいけません。** GitHub が用意している、載せても安全な「noreply アドレス」を使います。

1. https://github.com/settings/emails を開き、「Keep my email addresses private」にチェックを入れます。
2. 同じ画面に出る `<数字>+<ユーザー名>@users.noreply.github.com` の形のアドレスをコピーします。
3. 次を実行します（名前は、実名でなく GitHub のユーザー名でも構いません）。

```
git config --global user.name "<あなたの名前または GitHub のユーザー名>"
git config --global user.email "<noreply のアドレス>"
git config --global pull.ff only
```

設定を確かめます。メールアドレスが `@users.noreply.github.com` で終わっていれば OK です。

```
git config --global --get user.name
git config --global --get user.email
```

### A-6. Claude Code を入れる

```
curl -fsSL https://claude.ai/install.sh | bash
```

実行中は何も表示されませんが、そのまま待ちます。終わったら**新しいターミナルを開いて**確かめます。

```
claude --version
```

バージョンが出れば OK です。`command not found: claude` と出たときは、次を実行してから、新しいターミナルでもう一度確かめます。

```
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

### A-7. リポジトリを取得する

```
mkdir -p ~/repos
cd ~/repos
git clone https://github.com/nonooktk/oshiyobu_frontend.git
cd oshiyobu_frontend
```

### A-8. Claude Code を起動する

```
cd ~/repos/oshiyobu_frontend
claude
```

初回は次のことが起きます。

1. ブラウザが開くので、Claude のアカウントでログインする。
2. 「このフォルダを信頼しますか」という確認が出る。表示されるルールを読んで、このリポジトリで作業するなら `Yes` を選ぶ。

起動できたら、拒否の設定が読み込まれていることを確かめます。Claude Code の入力欄に次を打って、Enter を押します。

```
/permissions
```

拒否（Deny）の一覧に `Bash(git push ...)` などが並び、設定の出どころとして `.claude/settings.json` が出ていれば OK です。Esc で閉じます。

> **許可を求められたとき**: Claude Code は、コマンドを実行する前に「実行してよいか」を聞いてきます。内容を読んで、問題なければ 1 回だけ許可します。「今後は聞かない」という選択肢は選ばないでください。

### A-9. 最初にスキルを呼ぶ

Claude Code の入力欄に次を打って、Enter を押します。

```
/start-task
```

Claude が、今の状態の確認、最新の取得、ブランチの作成を進め、「やること」を日本語で書き出して止まります。内容を読んで、よければ「OK」と返します。直したいところがあれば、そのまま伝えます。

終わるときは、`exit` と打つか、`Ctrl + D` を 2 回押します。

## B. Windows の手順

Windows では、**WSL は要りません。** この文書は、Windows にそのまま入れる手順（ネイティブ版）で進めます。WSL を使うのは、Linux 用の道具を使いたい人や、コマンドの実行を隔離したい人だけです。

### B-1. PowerShell を開く

`Win + X` を押して、「ターミナル」または「Windows PowerShell」を選びます。**「Windows PowerShell (x86)」は選びません。** 行の先頭が `PS C:\Users\...>` なら PowerShell です。`PS` が付かない `C:\Users\...>` は CMD なので、この文書のコマンドは動きません。

### B-2. Git for Windows を入れる

```
winget install --id Git.Git -e --source winget
```

終わったら、PowerShell を**閉じて開き直し**、確かめます。

```
git --version
```

`winget` が使えないときは、https://git-scm.com/downloads/win からインストーラをダウンロードして実行します。画面はすべて「Next」を押して、既定のまま進めます。

Git for Windows を入れておくと、Claude Code が Git Bash を使えるようになります。

### B-3. Node.js を入れる

```
winget install OpenJS.NodeJS.LTS
```

`winget` が使えないときは、https://nodejs.org/en/download を開き、LTS の Windows 用インストーラ（.msi）をダウンロードして実行します。

PowerShell を**閉じて開き直し**、確かめます。

```
node --version
npm --version
```

必要な Node.js のバージョンは、「C. アプリの起動・テスト・ビルド」の表のとおりです（22 LTS の 22.22.2 以降、24 LTS の 24.15.0 以降、26 以降）。入れた版が合っているか、上の `node --version` で確かめます。

### B-4. GitHub CLI を入れて、GitHub にログインする

```
winget install --id GitHub.cli --source winget
```

終わったら、PowerShell を**閉じて、新しいウィンドウを開きます**（新しいタブでは足りません）。ログインします。

```
gh auth login
```

質問への答え方は、「A-4」と同じです。ログインできたことを確かめます。

```
gh auth status
```

### B-5. 作者の名前とメールアドレスを決める

「A-5」と同じ理由と手順です。**このリポジトリは公開されているので、個人のメールアドレスを載せてはいけません。**

1. https://github.com/settings/emails を開き、「Keep my email addresses private」にチェックを入れます。
2. 同じ画面に出る `<数字>+<ユーザー名>@users.noreply.github.com` の形のアドレスをコピーします。
3. 次を実行します（名前は、実名でなく GitHub のユーザー名でも構いません）。

```
git config --global user.name "<あなたの名前または GitHub のユーザー名>"
git config --global user.email "<noreply のアドレス>"
git config --global pull.ff only
```

設定を確かめます。メールアドレスが `@users.noreply.github.com` で終わっていれば OK です。

```
git config --global --get user.name
git config --global --get user.email
```

### B-6. Claude Code を入れる

```
irm https://claude.ai/install.ps1 | iex
```

実行中は何も表示されませんが、そのまま待ちます。終わったら**新しい PowerShell を開いて**確かめます。

```
claude --version
```

バージョンが出れば OK です。`claude is not recognized` と出たときは、次を実行してから、PowerShell を閉じて開き直し、もう一度確かめます。

```
$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
```

`irm is not recognized` と出たときは、CMD を開いています。B-1 に戻って、PowerShell を開き直します。

### B-7. リポジトリを取得する

```
New-Item -ItemType Directory -Force -Path "$HOME\repos"
Set-Location "$HOME\repos"
git clone https://github.com/nonooktk/oshiyobu_frontend.git
Set-Location oshiyobu_frontend
```

### B-8. Claude Code を起動する

```
Set-Location "$HOME\repos\oshiyobu_frontend"
claude
```

初回は次のことが起きます。

1. ブラウザが開くので、Claude のアカウントでログインする。
2. 「このフォルダを信頼しますか」という確認が出る。表示されるルールを読んで、このリポジトリで作業するなら `Yes` を選ぶ。

起動できたら、拒否の設定が読み込まれていることを確かめます。Claude Code の入力欄に次を打って、Enter を押します。

Claude Code の入力欄に次を打って、Enter を押します。

```
/start-task
```

Claude が、今の状態の確認、最新の取得、ブランチの作成を進め、「やること」を日本語で書き出して止まります。内容を読んで、よければ「OK」と返します。直したいところがあれば、そのまま伝えます。

## C. アプリの起動・テスト・ビルド

リポジトリを取得したフォルダ（`~/repos/oshiyobu_frontend`）で実行します。

| やること | コマンド |
| --- | --- |
| 必要な Node.js のバージョン | 22 LTS の 22.22.2 以降、24 LTS の 24.15.0 以降、26 以降。奇数の版（23・25）は対象外です。確かめ方: `node --version` |
| 依存パッケージのインストール | `npm ci` |
| アプリの起動（ローカル） | `npm run dev` |
| テスト | `npm test` |
| lint（書き方の検査） | `npm run lint` |
| 型チェック | `npm run typecheck` |
| ビルド | `npm run build`（出力は `dist/`） |
| ビルドの確認 | `npm run preview` |
| 整形 | `npm run format`（確認だけは `npm run format:check`） |
| 絵を差し替えたあと | `npm run images`（`assets-src/` の元絵から、表示の大きさの WebP を `src/assets/img/` に作る。`sharp` が動かない環境では、統括に依頼します） |
| 量の検査（ビルドのあと） | `npm run check:budget`（最初に読む JS と CSS が gzip で 200 KB 以下・絵の大きさ）／`npm run check:csp`（配信の設定の CSP） |
| core が手で直されていないかの検査 | `npm run core:check` |
| 実ブラウザの試験（任意） | `npm run e2e`（速さ・CSP・共有メーター。初回に `npx playwright install chromium`〈約 150 MB〉。手元の Google Chrome を使うなら、`E2E_CHANNEL=chrome npm run e2e` でダウンロード不要） |
| 手元の検査をまとめて（CI と同じ） | `npm run verify`（lint・型・整形・テスト・ビルド・量・CSP・core の検査を順に実行して、最後に結果をまとめる） |
| 検収（検査 → API → 画面の通信 → ひとり体験の通し） | `npm run accept -- --local-api`（手元の API を立てて確かめる。詳しくは `docs/検収.md`） |

`/pre-deploy-check` の「テストとビルドが通る」の項目は、`npm ci` のあと `npm run verify` を使います。`verify` は、lint・型・整形の確認・テスト・ビルド・`check:budget`・`check:csp`・`core:check` を順に実行し、エラーなしで通れば ○ です（CI の `verify` と同じ検査です）。

### 起動して画面を見る

1. `npm ci` を実行します（初回と、`package-lock.json` が変わったときだけ）。
2. `npm run dev` を実行します。`Local: http://localhost:5173/` と出れば、起動できています。止めるときは `Ctrl + C` を押します。
3. ブラウザで次の 3 つを開きます。どのページにも、札「デモ用の架空データ」が出ます。

| ページ | URL |
| --- | --- |
| 事務所向け | http://localhost:5173/ |
| ファン向け（QR の行き先） | http://localhost:5173/fan/ |
| 発表者用 | http://localhost:5173/presenter/ |

- **`/fan/` の最後の `/` を付けます。** `/fan` だけだと「見つかりません（404）」になります。
- 画面は、サーバー（API）につながなくても動きます。
- `src/core/` は手で直しません（backend で直して、`npm run core:sync -- <backend のコミット ID（40 桁）>` で置く決まりです。置き直すのは統括かコーディネーターで、担当者は実行しません。確認は `npm run core:check`）。

## D. つまずいたとき

| 症状 | 原因と直し方 |
| --- | --- |
| `command not found: claude` / `claude is not recognized` | Claude Code の置き場所が PATH に入っていません。A-6 または B-6 の PATH の手順を実行して、ターミナルを開き直します |
| `irm is not recognized` | PowerShell ではなく CMD を開いています。B-1 に戻ります |
| `git` や `gh`、`node` が見つからない | 入れた直後は、ターミナルを開き直さないと使えません。閉じて新しいウィンドウでもう一度実行します |
| `git clone` で `Repository not found` や 403 | GitHub にログインできていないか、権限がありません。`gh auth status` で確かめて、統括に権限を相談します |
| `git push` で 403 | 書き込み権限がありません。統括に、招待を依頼します |
| Claude Code が「denied（拒否）」と答える | このリポジトリでは禁止している操作です。迂回せず、そのまま統括に伝えます。拒否している操作の一覧は `docs/デプロイ手順.md` の末尾にあります |
| Claude Code にログインできない | 無料プランでは使えません。有料プランのアカウントか確かめます |
| Windows で `npm` を実行すると「このシステムではスクリプトの実行が無効」と出る | このエラーが出たときだけ、PowerShell で次を実行します: `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` |

それでも進めないときは、止まってください。実行したコマンドと画面の表示を**全文**コピーして、統括に聞きます。
