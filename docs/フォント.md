# フォント（書体 MOBO と Corporate Logo Rounded）と文字の大きさ

画面の書体は、次の 2 つです。どちらも、画面で使う字だけに絞った WOFF2 を、同じサイトの `/fonts/` から配ります（外部の配信は使いません。N-07）。

- **Corporate Logo Rounded Bold ver3**（LOGOTYPE.JP）: **ファン向け（`/fan/`）の全部**。
- **MOBO**（FLOP DESIGN）: 事務所向け（`/`）・発表者用（`/presenter/`）・収支シミュレーター（`/simulator.html`）。

統括の指示（2026-11-14）で入れた、**試しの切り替え**です。あとで戻しやすい形にしています（「4. 戻し方」）。経緯は、MOBO にする → 推し・応援の熱が出る所だけ Corporate Logo Rounded を当てる → 比較写真を見た統括の決定で、ファン向けは全部 Corporate Logo Rounded にする（版 B）、です。

## 1. どこにどの書体か

### 差し替え方（1 か所）

- `src/fan/main.tsx` が、ファン向けを開いたとき、根の要素（`html`）に `data-page="fan"` を付けます。
- `src/styles/tokens.css` の `:root[data-page='fan']` が、`--font` を `--font-fan`（先頭が Corporate Logo Rounded）に差し替えます。**ファン向けだけに効く、この 1 か所です。**
- 事務所向け・発表者用には `data-page` が付かないので、`--font` は MOBO のままです。
- `--font-fan` に MOBO は並べません。そのため、**ファン向けは MOBO を読み込みません**（読む WOFF2 は 1 本・130,184 B）。`body` も同じ書体にするため、`html` に付けています（`.shell` だけで差し替えると、`body` の MOBO が読み込まれてしまいます）。
- Corporate Logo Rounded に無い字（今は `✓` だけ）は、うしろの端末の書体で出ます。

### 太さが 1 本だけであることの影響

- Corporate Logo Rounded は、太さ 700 の 1 本だけです。CSS で 400 を指定した字（説明文・リストなど）も、**700 の面で出ます**（400 の面が無いので、ブラウザが 700 を使います。擬似の太字にはなりません）。
- そのため、ファン向けでは、本文と見出しの区別を、太さではなく、**大きさ・行間・色**で付けます（次の「2. 文字の大きさの段」）。

## 2. 文字の大きさの段（ファン向け）

統括の指示は、「タイトルをでかく、説明文を小さくして、フォントサイズにレイヤーをしっかり持たせる。行間は、文字が寄りすぎないよう、一定開ける」です。`src/fan` の文字の大きさは、`src/styles/tokens.css` の段のトークン（`--fs-*`）だけで決めます（px の直書きは、演出の中だけ）。

| 段 | トークン | 大きさ | 行間 | 当てた場所 |
| --- | --- | --- | --- | --- |
| hero | `--fs-hero` | 96px | 1 | 演出の大きい数字（80%・成立。実際の大きさは演出が決める `--fx-size`）。絵が無いときの頭文字 |
| figure | `--fs-figure` | 40px | 1 | 背の高いスマホ（高さ 760px 以上）の、メーターの「あと N 人」の数字だけ |
| title | `--fs-title` | 30px | 1.3 | 画面のタイトル（はじめの画面 `.stH`）・シートの見出し（`.sheet h2`）・特典の見出し（`.gStep`）・主な金額（`.rcPrice`・`.nxV`）・共有の画像の文（`.shareBig`）・メーターの「あと N 人」（`.gLeft b`。背の高いスマホは figure） |
| lead | `--fs-lead` | 22px | 1.3 | アプリバーの題（`.dHead h2`。幅 340px 以下は body）・カードや項目の名前（`.rcName`・`.nxRow b`・`.thanksName`）・次のアクションの題（`.nxL`・`.nxMet`）・メニューの区画の見出し（`.homeH`・`.actH`）・「達成率」の数字（`.gPct b`）・大きい説明（`.bigV`・`.aonBig`）・席の金額（`.seatOpt .p`）・「ライブの開催が決まりました」（`.gLeft b.gEst`） |
| body | `--fs-body` | 16px | 1.6（ボタン・1 行の題は 1.3） | 本文・ボタン・セリフ（`.bubble`・`.gSay`・`.thanksText`）・メニューの項目（`.tile`）・リスト（`.rcLi`・`.ck li`・`.flow li`）・「やめる」などのリンク |
| note | `--fs-note` | 13px | 1.7 | 説明文・注記・条件・札・ラベル（`.rcNote`・`.rcInfo`・`.nxRow small`・`.shareNote`・`.stVenue`・`.chip`・`.toast`・`.rows dt` など）。アプリバーの「戻る」「メニュー」も note |

- **字間**: `--ls-text` = 0.03em。ファン向けの根（`.shell`）に付け、全体に効きます。太字の丸い書体は字が詰まって見えるので、少し開けます。0・0.02em・0.03em・0.04em を、複数行の文（投稿文・注記・説明）の写真で比べて決めました。数字の大きい字（メーターの数字）は、従来の詰め（-0.03em）のままです。
- **行間のトークン**: `--lh-tight` = 1.3（1 行の題・ボタン）、`--lh-body` = 1.6（数行の文）、`--lh-note` = 1.7（説明文・注記）。数字・アイコンの 1〜1.2 と、1 行の固定（px）だけ、直書きです。
- **決まり**（`tests/unit/type-scale.test.ts` が検査します）:
  - となり合う段の比は 1.2 倍以上。note は 12px 以上。タイトルは 26〜30px。
  - `src/fan` の `font-size` は、段のトークンだけ。演出（`.ttl`・`.fxSub`・`.fxSay`・`.sayAv`・`.ach*`）の中だけ、px の直書きを許します（見え方を変えないため）。
  - 使っていない段（死んだトークン）が無い。TSX に `fontSize` の直書きが無い。
- **段を変えたいとき**: `tokens.css` の値を 1 つ直せば、全画面に効きます。1 つの文だけ段を変えるときは、その規則の `font-size` を、別の段のトークンに替えます。
- 事務所向け・発表者用・収支シミュレーターの文字の大きさは、変えていません。

## 3. 配っているファイル

置き場は `public/fonts/` です。

| ファイル | 書体・太さ | 読むページ | 大きさ |
| --- | --- | --- | --- |
| `Corporate-Logo-Rounded-Bold-ver3.woff2` | Corporate Logo Rounded 700（1 本だけ） | ファン向け | 130,184 B |
| `MOBO-Regular.woff2` | MOBO 400 | 事務所向け・発表者用・シミュレーター | 108,844 B |
| `MOBO-Bold.woff2` | MOBO 700 | 同上 | 117,328 B |
| `MOBO-Regular-sim.woff2` | MOBO 400（シミュレーターだけの字） | `/simulator.html` | 151,100 B |
| `MOBO-Bold-sim.woff2` | MOBO 700（同上） | `/simulator.html` | 168,804 B |
| `simulator.css` | シミュレーター用の `@font-face`（自動で書く） | `/simulator.html` | 約 10 KB |
| `glyphs.txt` | 収録した字の一覧（自動で書く） | — | 約 7 KB |
| `LICENSE_OFL_MOBO.txt`・`LICENSE_OFL_Corporate-Logo-Rounded.txt` | 書体ごとのライセンス文 | — | 各 4.3 KB |

- 上 3 本（**核**）の合計は 356,356 B です。上限は 400,000 B（`scripts/budget-lib.mjs` の `FONT_LIMIT`。`npm run check:budget` が検査します）。ページごとに実際に読む量は、ファン向け 130,184 B（1 本）、事務所向け・発表者用 226,172 B（MOBO 2 本）です。
- 下 2 本（**追加**）は、収支シミュレーターにだけ出る字（会場の名前の漢字など。676 字）です。その字が画面に出たときだけ読み込まれます（`unicode-range`）。合計 319,904 B。上限は 400,000 B（`FONT_SIM_LIMIT`）。
- Corporate Logo Rounded は、本文（MOBO の核）と同じ字の集合（689 字）に絞っています。ファン向けの字は、すべてここに入っています（漏れの検査が、ファン向けを含む画面の字を突き合わせます）。
- 数字は 2026-11-14 の値です。字が増えると変わります（`npm run fonts:build` のあとの出力で分かります）。

### 読み込みの決まり

- `font-display: swap`: 書体が届くまでは、うしろの書体（端末の日本語ゴシック）で出し、届いたら置き換えます。
- **`preload` は付けません。** 付けると、最初の表示の時刻（`oshiyobu:ready`）が、弱い回線で約 0.3 秒遅れました（「8. 量と速さの実測」）。
- 配信のヘッダー（`public/staticwebapp.config.json`）で、`/fonts/*` は 1 日（`max-age=86400`）キャッシュします。ファイル名にハッシュが無いので、変わらない扱い（`immutable`）にはしていません。CSP は変えていません（`font-src` を足さず、`default-src 'self'` のまま）。

## 4. 戻し方

- **いちばん簡単な戻し方**: 戻したい分の `git revert <コミットの ID>` で戻ります（PR の説明にコミットの一覧があります）。
- **ファン向けを MOBO に戻す**: `src/styles/tokens.css` の `:root[data-page='fan']` の規則と、`src/fan/main.tsx` の `data-page` の 1 行を消します（テスト `tests/unit/fonts.test.ts` の該当の検査も直します）。文字の大きさの段は、そのまま使えます。
- **MOBO もやめる**: `src/styles/tokens.css` の `--font` の先頭の `'MOBO', ` を消し、`public/simulator.html` の `--font` も同じに直します。`@font-face` は、使われなければ読み込まれないので、残して構いません。
- 完全に外すときは、`public/fonts/`・`src/styles/fonts.css`（と `tokens.css` の `@import`）・`scripts/fonts-*`・`package.json` の `fonts:build`・`tests/unit/fonts.test.ts` を消します。

## 5. 画面の字を足したとき（テストが落ちたとき）

画面に新しい漢字などを足すと、`npm test` の「画面に出る字が、フォントに入っている」が落ちます。メッセージに、漏れた字と、見つけたファイルが出ます。落ちたら、フォントを絞り直します。

```
npm run fonts:build -- --src <MOBO のフォルダ> --display-src <Corporate Logo Rounded のフォルダ>
```

- 要るもの: **Python 3.8 以上と fonttools・brotli**。`python3 -m pip install fonttools brotli`（Windows は `py -m pip install fonttools brotli`）。
- 元のフォント（OTF）は、**リポジトリに入れません**（合計 25 MB 以上）。手元の、リポジトリの外のフォルダに置きます。
- 実行すると、画面の字を集め（`scripts/fonts-lib.mjs`）、元の OTF から切り出して（`scripts/fonts-subset.py`）、WOFF2・ライセンス文・`glyphs.txt`・`simulator.css` を `public/fonts/` に書きます。
- 終わったら、`npm test`・`npm run build`・`npm run check:budget` を通します。
- Python が入っていない・元のフォントが無いときは、絞り直さずに、漏れた字の一覧を添えて、コーディネーターに頼んでください。漏れた字は、絞り直すまで、端末の書体で表示されます（読めなくなることはありません）。

### 何を残しているか

- 字: 画面に出る字（`src/` の文字列・テンプレート・JSX の文・CSS の `content`、各 HTML、`public/simulator.html`。**コメントは数えない**）に、ASCII・ひらがな・カタカナの全字、記号、日付や金額を組み立てるときの字を足したもの。
- OpenType の機能: `kern`（字間）・`ccmp`・`liga` だけ。縦書き（`vert` など）・`palt` は外しています。縦書きの表（`VORG`・`vhea`・`vmtx`）も外しています。
- **輪郭が空の字は入れません。** 元の書体には、字は登録されているのに、形が無い（幅だけの）字があります。MOBO の Bold の `‹ › ‼ · – — • ゕ ゖ`（Regular には形があります）です。入れると、画面では何も出ず、端末の書体にも落ちません（変更前の版で、ホームの「次のアクション ›」の `›` が消えた原因）。400・700 の**どちらかで形が空の字は、両方から外し**、端末の書体で出します（`glyphs.txt` の `[なし]`）。見出し書体（Corporate Logo Rounded）には、空の字がありません。
- 書体の名前・著作権表示（name 表）は、元のまま残しています。名前を変えて別の書体として配ることはしません。

### 漏れの検査（テスト）

`tests/unit/fonts.test.ts` が、次を検査します。Python は要りません（Node だけで動きます）。

- 画面の字が、`glyphs.txt` の一覧に載っている（漏れが 0 字）。
- `glyphs.txt` が、実際に配る WOFF2 の中身（cmap）と一致している（一覧だけを手で直しても通らない）。
- `public/fonts/` に、決めたファイルだけがある（元の otf・ttf が混ざっていない）。ライセンス文が揃っている。
- **配る WOFF2 のどれにも、輪郭が空の字（空白類を除く）が 1 つも無い**（`readWoff2EmptyGlyphs` が、CFF の charstring を読んで調べる。5 本とも 0 件）。`‹ ›` などが `[なし]` にあることも検査します。
- `simulator.css` が、一覧から作った中身と同じ。
- 見出し書体を当てる場所の一覧が、CSS・テスト・この文書で同じ。

**検査できないこと**: 通信で届く字（API の応答の文字など）は、ソースに無いので集められません。MOBO に無い字（`✓` と、形が空のため外した `‹ › ‼ · – — • ゕ ゖ`）は、端末の書体で表示されます。

## 8. 量と速さの実測

条件は、下り 1600 kbps（200,000 B/秒）・上り 750 kbps・遅延 150 ms・CPU 4 倍、手元の Chrome（Playwright）、毎回まっさらな状態（冷たい読み込み）、各 5 回です。表の値は、最初の表示の印 `oshiyobu:ready` の時刻（ミリ秒）の中央値です。

| 版 | ファン向け `/fan/?p=4` | 事務所向け `/` |
| --- | --- | --- |
| 文字の大きさの段の前（`origin/dev`。MOBO + 見出しは推しの所だけ） | 991（981〜1002） | 911（893〜921） |
| 段の後（ファン向けは全部 Corporate Logo Rounded・`preload` なし） | 997（993〜999） | 916（907〜924） |
| （参考）見出し書体だけ `preload` した試し（以前の版） | 1284 | — |

- **`preload` なしでは、最初の表示は、ほぼ変わりません。** `preload` を付けると、約 0.26〜0.28 秒遅れます。書体の要求が、最初の JS と、同じ回線を取り合うためです。そのため、付けません。
- ファン向けが読む WOFF2 は、**3 本（356,356 B）から 1 本（130,184 B）に減りました**（MOBO を読み込まなくなったため）。書体が届くのは、最初の表示のあと（約 2.9 秒後。前は約 4.2 秒後）です。それまでは、端末の書体で出て、届くと置き換わります（`font-display: swap`）。
- 書体が当たったことの確認（ファン向け）: `document.fonts` の MOBO の 2 面が `unloaded`、Corporate Logo Rounded が `loaded`。`body` の計算済みの `font-family` が `"Corporate Logo Rounded Bold ver3", "Noto Sans JP", …`。
- ホーム（幅 320×640・320×568・360×640・375×667・375×812・390×844）は、段の前後とも、1 画面に収まる（ページ内のスクロール 0px・一番下のボタンが画面の中）。押せる部品は 44px 以上です。
