# フォント（書体 MOBO と Corporate Logo Rounded）

画面の書体は、次の 2 つです。どちらも、画面で使う字だけに絞った WOFF2 を、同じサイトの `/fonts/` から配ります（外部の配信は使いません。N-07）。

- **MOBO**（FLOP DESIGN）: 本文の書体。全ページ。
- **Corporate Logo Rounded Bold ver3**（LOGOTYPE.JP）: 推し・応援の熱が出る所だけに当てる書体。**ファン向け（`/fan/`）だけ**。

統括の指示（2026-11-14）で入れた、**試しの切り替え**です。あとで戻しやすい形にしています（「3. 戻し方」）。

## 1. どこに当てているか

### 意図

統括の言葉は、「推しにかかわる文字部分を、オタクが推しを応援する雰囲気を出すために使いたい。例えば、エフェクトもそう」です。そのため、**推し・応援の熱が出る所だけ**に、丸い太字の Corporate Logo Rounded を当てます。手続き・お金・説明・業務の画面には当てず、MOBO のままにします。

### 当てている場所（ファン向け `/fan/` だけ）

当てる場所は、`src/fan/fan.module.css` の末尾にある **1 つの規則**（`font-family: var(--font-display)`）の一覧がすべてです。

| セレクタ | 当てている場所 |
| --- | --- |
| `.heroWho` | 推しの名前の帯（はじめの画面の推しの名前、ホームの「◯◯を△△市に呼ぶ」） |
| `.who` | 推しのセリフの話し手の名前 |
| `.oshiTitle` | 見出し「推しを選ぶ」（はじめの画面の 1 ステップ目だけ） |
| `.ttl` | 80% 突破・成立の演出の大きい文字 |
| `.fxSub` | 同じ演出の下の文字 |
| `.achC` | 条件がそろったときの演出の文字（「条件がそろいました」など） |
| `.gStep` | 「特典 n/3 が開きました」 |
| `.gLeft b` | メーターの「あと N 人」の数字 |
| `.gPct` | メーターの「達成率 N%」 |
| `.shareFrame` | 共有の画像の中の文 |
| `.shareTitle` | 共有の画面の見出し |

### 当てていない場所（MOBO のまま）

- 推しのセリフの本文・感謝のメッセージの本文（小さい字で数行あり、読みやすさを優先。統括に確認中で、あとで当てる側に変わるかもしれません）
- 「次のアクション」などのボタン（同じく確認中）
- 手順の見出し「呼びたい市を選ぶ」「目指すコースを選ぶ」
- コースの金額・支払いの説明・条件・シートの見出し・札・注記
- 事務所向け（`/`）・発表者用（`/presenter/`）・収支シミュレーター（`/simulator.html`）の全部

### 範囲を足し引きするとき

3 か所を、同じ内容に直します。テスト（`tests/unit/fonts.test.ts`）が、3 か所が合っていることを検査します。

1. `src/fan/fan.module.css` の末尾の規則（セレクタを 1 行足す・消す）
2. `tests/unit/fonts.test.ts` の `DISPLAY_SELECTORS`
3. この文書の上の表

新しい場所に当てたいクラスが、その部品の CSS にまだ無いときは、部品（TSX）にクラスを足します（`.oshiTitle`・`.shareTitle` がその例です）。

## 2. 配っているファイル

置き場は `public/fonts/` です。

| ファイル | 書体・太さ | 読むページ | 大きさ |
| --- | --- | --- | --- |
| `MOBO-Regular.woff2` | MOBO 400 | 全ページ | 108,844 B |
| `MOBO-Bold.woff2` | MOBO 700 | 全ページ | 117,328 B |
| `Corporate-Logo-Rounded-Bold-ver3.woff2` | Corporate Logo Rounded 700（1 本だけ） | ファン向け | 130,184 B |
| `MOBO-Regular-sim.woff2` | MOBO 400（シミュレーターだけの字） | `/simulator.html` | 151,100 B |
| `MOBO-Bold-sim.woff2` | MOBO 700（同上） | `/simulator.html` | 168,804 B |
| `simulator.css` | シミュレーター用の `@font-face`（自動で書く） | `/simulator.html` | 約 10 KB |
| `glyphs.txt` | 収録した字の一覧（自動で書く） | — | 約 7 KB |
| `LICENSE_OFL_MOBO.txt`・`LICENSE_OFL_Corporate-Logo-Rounded.txt` | 書体ごとのライセンス文 | — | 各 4.3 KB |

- 上 3 本（**核**）の合計は 356,356 B です。上限は 400,000 B（`scripts/budget-lib.mjs` の `FONT_LIMIT`。`npm run check:budget` が検査します）。
- 下 2 本（**追加**）は、収支シミュレーターにだけ出る字（会場の名前の漢字など。676 字）です。その字が画面に出たときだけ読み込まれます（`unicode-range`）。合計 319,904 B。上限は 400,000 B（`FONT_SIM_LIMIT`）。
- 見出し書体は、当てる範囲が変わっても字の漏れが出ないよう、本文（MOBO の核）と同じ字の集合に絞っています（689 字。見出し書体には、MOBO が外した ‹ › などの形があるので、MOBO の核（681 字）より多い）。
- 数字は 2026-11-14 の値です。字が増えると変わります（`npm run fonts:build` のあとの出力で分かります）。

### 読み込みの決まり

- `font-display: swap`: 書体が届くまでは、うしろの書体（端末の日本語ゴシック）で出し、届いたら置き換えます。
- **`preload` は付けません。** 付けると、最初の表示の時刻（`oshiyobu:ready`）が、弱い回線で約 0.3 秒遅れました（「7. 量と速さの実測」）。
- 配信のヘッダー（`public/staticwebapp.config.json`）で、`/fonts/*` は 1 日（`max-age=86400`）キャッシュします。ファイル名にハッシュが無いので、変わらない扱い（`immutable`）にはしていません。CSP は変えていません（`font-src` を足さず、`default-src 'self'` のまま）。

## 3. 戻し方

- **いちばん簡単な戻し方**: コミットを、配信のしくみ・書体の指定（`--font`・`--font-display`）・見出し書体を当てる範囲、の 3 つに分けてあります。戻したい分の `git revert <コミットの ID>` で戻ります（PR の説明にコミットの一覧があります）。
- **見出し書体をやめる**: `src/fan/fan.module.css` の末尾の規則（`font-family: var(--font-display)`）を消します。あわせて、`tests/unit/fonts.test.ts` の `DISPLAY_SELECTORS` と、この文書の上の表も直します（テストが、3 か所の一致を検査するため）。
- **MOBO もやめる**: `src/styles/tokens.css` の `--font` の先頭の `'MOBO', ` を消し、`public/simulator.html` の `--font` も同じに直します。`@font-face` は、使われなければ読み込まれないので、残して構いません。
- 完全に外すときは、`public/fonts/`・`src/styles/fonts.css`（と `tokens.css` の `@import`）・`scripts/fonts-*`・`package.json` の `fonts:build`・`tests/unit/fonts.test.ts` を消します。

## 4. 画面の字を足したとき（テストが落ちたとき）

画面に新しい漢字などを足すと、`npm test` の「画面に出る字が、フォントに入っている」が落ちます。メッセージに、漏れた字と、見つけたファイルが出ます。落ちたら、フォントを絞り直します。

```
npm run fonts:build -- --src <MOBO のフォルダ> --display-src <Corporate Logo Rounded のフォルダ>
```

- 要るもの: **Python 3.8 以上と fonttools・brotli**。`python3 -m pip install fonttools brotli`（Windows は `py -m pip install fonttools brotli`）。
- 元のフォント（OTF）は、**リポジトリに入れません**（合計 25 MB 以上）。手元の、リポジトリの外のフォルダに置きます。
- 実行すると、画面の字を集め（`scripts/fonts-lib.mjs`）、元の OTF から切り出して（`scripts/fonts-subset.py`）、WOFF2・ライセンス文・`glyphs.txt`・`simulator.css` を `public/fonts/` に書きます。
- 終わったら、`npm test`・`npm run build`・`npm run check:budget` を通します。
- Python が入っていない・元のフォントが無いときは、絞り直さずに、漏れた字の一覧を添えて、コーディネーターに頼んでください。漏れた字は、絞り直すまで、端末の書体で表示されます（読めなくなることはありません）。

### 何を残しているか

- 字: 画面に出る字（`src/` の文字列・テンプレート・JSX の文・CSS の `content`、各 HTML、`public/simulator.html`。**コメントは数えない**）に、ASCII・ひらがな・カタカナの全字、記号、日付や金額を組み立てるときの字を足したもの。
- OpenType の機能: `kern`（字間）・`ccmp`・`liga` だけ。縦書き（`vert` など）・`palt` は外しています。縦書きの表（`VORG`・`vhea`・`vmtx`）も外しています。
- **輪郭が空の字は入れません。** 元の書体には、字は登録されているのに、形が無い（幅だけの）字があります。MOBO の Bold の `‹ › ‼ · – — • ゕ ゖ`（Regular には形があります）です。入れると、画面では何も出ず、端末の書体にも落ちません（変更前の版で、ホームの「次のアクション ›」の `›` が消えた原因）。400・700 の**どちらかで形が空の字は、両方から外し**、端末の書体で出します（`glyphs.txt` の `[なし]`）。見出し書体（Corporate Logo Rounded）には、空の字がありません。
- 書体の名前・著作権表示（name 表）は、元のまま残しています。名前を変えて別の書体として配ることはしません。

### 漏れの検査（テスト）

`tests/unit/fonts.test.ts` が、次を検査します。Python は要りません（Node だけで動きます）。

- 画面の字が、`glyphs.txt` の一覧に載っている（漏れが 0 字）。
- `glyphs.txt` が、実際に配る WOFF2 の中身（cmap）と一致している（一覧だけを手で直しても通らない）。
- `public/fonts/` に、決めたファイルだけがある（元の otf・ttf が混ざっていない）。ライセンス文が揃っている。
- **配る WOFF2 のどれにも、輪郭が空の字（空白類を除く）が 1 つも無い**（`readWoff2EmptyGlyphs` が、CFF の charstring を読んで調べる。5 本とも 0 件）。`‹ ›` などが `[なし]` にあることも検査します。
- `simulator.css` が、一覧から作った中身と同じ。
- 見出し書体を当てる場所の一覧が、CSS・テスト・この文書で同じ。

**検査できないこと**: 通信で届く字（API の応答の文字など）は、ソースに無いので集められません。MOBO に無い字（`✓` と、形が空のため外した `‹ › ‼ · – — • ゕ ゖ`）は、端末の書体で表示されます。

## 6. ライセンス

- どちらも **SIL Open Font License 1.1**。元は Adobe の源ノ角ゴシック（Source Han Sans）です。
- OFL の条件のうち、この画面に関わるもの:
  - ライセンス文を、書体と一緒に配る（`public/fonts/` に、書体ごとに置いています）。
  - 書体の名前を変えて、別の書体として配らない。単体で売らない。
  - 著作権表示を残す（WOFF2 の name 表に、元のまま残しています）。
- 著作権表示: MOBO は「Copyright 2014 Adobe Systems Incorporated」、Corporate Logo Rounded は「LOGOTYPE.JP [Source Han Sans] © 2014-2020 Adobe, with Reserved Font Name 'Source'」です。この書体は、名前を「Source」から変えて配られているものです。こちらでも、名前は変えていません。

## 7. 量と速さの実測

2026-11-14。条件は、下り 1600 kbps（200,000 B/秒）・上り 750 kbps・遅延 150 ms・CPU 4 倍、手元の Chrome（Playwright）、毎回まっさらな状態（冷たい読み込み）、各 5 回です。表の値は、最初の表示の印 `oshiyobu:ready` の時刻（ミリ秒）の中央値です（5 回の幅は、ファン向け 987〜1037・事務所向け 898〜961）。

| 版 | ファン向け `/fan/?p=4` | 事務所向け `/` |
| --- | --- | --- |
| 変更前（`origin/dev`） | 995 | 912 |
| 変更後（3 本・`preload` なし） | 1000 | 925 |
| 見出し書体だけ `preload`（ファン向けの HTML に付けた試し） | 1284 | — |
| MOBO の Bold だけ `preload`（MOBO 2 本の構成のとき） | 1279 | 1178 |
| MOBO の Regular だけ `preload`（同上） | 1283 | 1160 |

- **`preload` なしでは、最初の表示は、ほぼ変わりません**（+5 ms・+13 ms。5 回の幅の中）。`preload` を付けると、約 0.26〜0.28 秒遅れます。書体の要求が、最初の JS と、同じ回線を取り合うためです。そのため、付けません。
- 書体が届くのは、最初の表示のあとです。ファン向けは約 4 秒後（核 3 本の 357 KB が、最初の画面の絵と回線を分け合う）、事務所向けは約 2.4 秒後（核 2 本）。それまでは、端末の書体で出て、届くと置き換わります（`font-display: swap`）。
- 最初に読む JS と CSS（gzip）は、事務所向け 82,777 → 82,915 B・ファン向け 101,174 → 101,401 B・発表者用 71,840 → 71,967 B（+127〜+227 B。`@font-face` と `--font` の分）。上限 200,000 B のまま。
- 事務所向けは、見出し書体を読み込みません（MOBO の 2 本だけ）。
- 書体が当たったことの確認: `document.fonts.check('700 24px "Corporate Logo Rounded Bold ver3"')` が `true`、`document.fonts` の 3 面が `loaded`、当てた要素の計算済みの `font-family` が `"Corporate Logo Rounded Bold ver3", MOBO, …` になっている。
- 幅 320・375・390 のファン向けと、事務所向け 1280×720・1440×900 で、はみ出しの新規は 0 件、ホームの 1 画面に収まる状態（320×640・375×667・390×844）も変わらないことを確かめました。折り返しの行数が変わったのは、幅 320 の共有シートの注記 1 か所（2 行 → 3 行）だけです。
