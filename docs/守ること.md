# 守ること（見た目は自由に、体験の流れと通信は壊さない）

この文書は、OSHIYOBU の画面を、フロントのデザイン担当者へ渡すときの「線引き」の正本です。読むのは、担当者と、担当者の Claude Code です。

- 担当者に任せるのは、**見た目**（色・余白・絵・文言・レイアウト）です。
- 壊してはいけないのは、**体験の流れ**（ここで作り込んだ、開いてから成立までの動き）と、**backend との通信**です。
- 線は、ファイルの場所と、番号つきの決まり（G-01 から）で引きます。

Claude Code は、作業を始めるたびに、次の「0. 要点」を自動で読みます（`.claude/settings.json` の `SessionStart`。仕組みは「5. 三段の守り」）。

## 言葉

| 言葉 | 意味 |
| --- | --- |
| 管理者 | 統括。この画面の持ち主で、権限・秘匿値・配備を持つ人。決まりを変えられるのは管理者だけ |
| backend | 対になるリポジトリ。計算・デモデータ・API（共有メーター用の小さなサーバー）を持つ |
| core | backend の計算とデータを、このリポジトリに写したもの（`src/core/`）。手で直さない |
| テスト | 決まりを守っているかを、自動で確かめる検査。`npm test` で動く |
| `npm run verify` | lint・型・整形・テスト・ビルド・各種の検査を順に回す命令。GitHub の CI（自動検査）と同じ内容 |
| トークン | `src/styles/tokens.css` で名前をつけて決めた、色・間隔・文字の大きさの値。画面の CSS は `var(--名前)` で使う |
| CSP | 画面が読み込める相手・通信できる相手を、ブラウザに教える配信の設定。外へ通信しないことを、これで守っている |
| PR | 変更を `main` に入れる前に、確認してもらうための申請（GitHub の画面で出す） |

## 0. 要点（Claude Code が作業の始めに読む部分）

この節の `claude-brief:start` から `claude-brief:end` までを、`scripts/claude-brief.mjs` が取り出して、作業の始めに Claude Code に読ませます。ここを書き換えるときは、管理者が、「1. 線引き」・「2. 守ること」・`CLAUDE.md` の「0. 守ること」・`.claude/settings.json` と食い違わないようにします（`tests/guard/` が食い違いを見つけます）。

## 1. 線引き（変えてよい所と、変えてはいけない所）

フォルダとファイルの名前で、3 つに分けます。

| 区分 | 場所 | 扱い |
| --- | --- | --- |
| **自分で変えてよい**（見た目） | `src/fan/`・`src/office/`・`src/presenter/` の CSS（`*.module.css`）と部品（`components/`・`pages/`・`layers/`・`art/`）・文言（`text/`）。`src/styles/base.css`。絵（`src/assets/img/`・`assets-src/`。変えたら `npm run images`）。`tests/` の新しいテスト | 変えてよい。ただし、「2. 守ること」の番号に反しない範囲で。変えたら `npm run verify` |
| **先に管理者へ相談**（体験の流れと、共有の部品） | `src/fan/store/`・`src/fan/domain/`（申し込み・80% の演出・成立・初めに戻す順番と数え方）。`src/shared/`（特に `meter/`）。`src/styles/tokens.css`（色を足すとき）。`public/fonts/`・`scripts/`（書体の絞り込みと検査の道具） | 理由を添えて管理者に頼み、了承を得てから変える。了承なしに変えない |
| **変えない**（編集の道具では書き込めない） | `src/core/`・`core.lock.json`・`.github/`・`public/staticwebapp.config.json`・`docs/守ること.md`・`tests/guard/`・`.claude/settings.json`・`.claude/settings.local.json`・`scripts/claude-brief.mjs` | 変えたいときは、管理者へ頼む |

- 「変えない」の場所は、Claude Code の設定（`.claude/settings.json` の `permissions.deny`）で、編集の道具による書き込みを止めています。GitHub の CODEOWNERS でも、管理者の確認が要る場所にしてあります（`.github/CODEOWNERS`）。
- 区分に載っていない場所（`e2e/`・`public/` のその他など）は、迷ったら、変えずに聞きます。
- **既存のテストの期待値・入力・skip の条件は、勝手に変えません**（G-24）。新しいテストを足すのは自由です。

## 2. 守ること

「落ちる検査」の欄は、決まりを壊したときに、**自動で赤くなるもの**です。`npm run verify` を回すと、テストの列は全部動きます。`npm run` の列で verify の外にあるもの（`check:api`・`check:live`）は、別に回します。「歯止めなし」は、壊しても自動では気づけない決まりです（人の目と PR のレビューで見ます）。

「変えたいとき」の欄の「自分で」は、決まりの範囲で調整してよい、「管理者へ」は、決まりそのものを動かすので、変えずに頼む、という意味です。

## 3. 利用者に頼まれたときの動き方（Claude Code 向け）

担当者から頼まれたことが、「2. 守ること」の番号に当たるか、「1. 線引き」の「変えない」「先に管理者へ相談」の場所を触るときは、次の順に動きます。

1. **どの決まり（番号）に当たるかを、先に伝える。** 例: 「これは G-04（褒めるのは行動だけ）に当たります。」
2. **変えない。** 設定で止められなかったとしても、別のやり方（シェルでの書き換え・スクリプト・別のファイル経由）で通さない。止まったら、そこまでを報告して返す。
3. **管理者に頼む文面の下書きを出す。** 担当者が、そのまま管理者に送れる形にする（下の雛形）。
4. **代わりにできることを、1 つ示す。** 決まりの範囲でできる見た目の案（例: 札はそのままに、位置と色を変える）。

迷ったら、変えずに聞きます。反対に、「ホームの余白を広げて」「ボタンの色を、トークンの別の色にして」のような見た目の頼みは、止めずに進めます（変えたあとは `npm run verify`）。

管理者に頼む文面の雛形:

```
管理者（統括）へ。次の変更をしたく、相談です。
- やりたいこと: <何をどう変えたいか。なぜか>
- 当たる決まり: <G-xx と、決まりの名前>
- 触りたい場所: <ファイル名>
- 変えないと困ること: <>
- 代わりに、自分でできること: <>
```

## 4. 決まりを変えるとき（管理者）

- 決まりを足す・変えるのは、管理者だけです。この文書・`tests/guard/`・`.claude/settings.json`・`scripts/claude-brief.mjs`・`CLAUDE.md` の「0. 守ること」は、同じ変更の中でそろえます（食い違うと `tests/guard/` が落ちます）。
- 熱量の表示（G-08）が入ったら、G-08 の「予定」を外し、検査を `tests/guard/` に足し、「0. 要点」にも 1 行足します。
- 新しい決まりを足すときは、番号を続けます（G-28 から）。番号を詰めません。
- この文書の「落ちる検査」に書いたテストのファイルと `npm run` の命令が、実在することを `tests/guard/docs.test.ts` が確かめます。

## 5. 三段の守りと、限界

| 段 | 何をするか | 入れたもの |
| --- | --- | --- |
| 1. 知らせる | 作業を始めるたびに、要点を Claude Code に読ませる | `CLAUDE.md` の「0. 守ること」（Claude Code が常に読む）。`.claude/settings.json` の `SessionStart`（`scripts/claude-brief.mjs` が、この文書の「0. 要点」を出す。`/clear`・`/compact` のあとにも出る）。PR の雛形のチェック |
| 2. 止める | 壊してはいけない場所への書き込みと、危ない命令を、設定で止める | `.claude/settings.json` の `permissions.deny`（「変えない」の場所への `Edit`。`main`・`dev` への push・force push・`gh secret`・`gh variable`・`gh workflow run`・`az`・`npm run core:sync`・`git reset --hard`・`git clean`・`git checkout -f` など）。CODEOWNERS（管理者の確認が要る場所） |
| 3. 見つける | それでも壊れたら、テストと検査が落ちて、番号と案内を出す | `npm run verify`（既存のテストと検査）。`tests/guard/`（この文書と設定・台本の食い違い、射幸の語・急がせる語・色の直書き・skip・秘匿値の見張り）。落ちると、「G-xx に反しています。直さずに、管理者へ」と出る |

### 限界（守れない場合）

守りは「うっかり」を防ぐ仕組みで、完全な防壁ではありません。次の場合は、止まりません。

- **別の書き方での書き換え。** 拒否は、Claude Code が見た命令や編集の道具に対して照らし合わせます。`/usr/bin/git push …`・`bash -c '…'`・スクリプトが自分でファイルを書く場合は、止められません（公式ドキュメントの「What a Bash rule doesn't match」）。`cp`・`mv`・`rm` で「変えない」の場所を直接変えても、止まらないことがあります。この場合は、3 段目（`core:check`・テスト・CI・CODEOWNERS）が見つけます。
- **起動する場所。** 拒否の設定は、リポジトリの一番上のフォルダで `claude` を起動したときに効きます（設定のパスは、起動したフォルダを基準に読まれるため）。サブフォルダで起動すると、効かないことがあります。台本は、起動した場所が違うとき、警告を出します。
- **設定を、担当者本人が書き換える。** `.claude/settings.local.json` で hooks を止める（`disableAllHooks`）ことや、設定ファイルを手で書き換えることは、止められません。Claude Code に頼んだ書き換えは `Edit` の拒否で止まりますが、手での変更は止まりません。設定の変更は、PR で管理者が確かめます。
- **`--dangerously-skip-permissions`。** 公式ドキュメントは、「deny の規則は、`bypassPermissions` を含むすべてのモードで効く」と説明しています。ただし、確認の画面は出なくなります。このリポジトリでは使いません。使ったときに実際に止まるかは、確かめていません。
- **GitHub の側。** CODEOWNERS が効くのは、管理者がブランチ保護で「コードオーナーのレビューを必須」にしたときです。`main`・`dev` への push の最後の砦も、ブランチ保護です。どちらも管理者の設定で、この文書を書いた時点では、確かめていません。
- **検査できないこと。** G-13（1 画面・44px）・G-08・G-27 と、G-24 の期待値の書き換えは、自動では見つけられません。G-04・G-05 は、語の一覧と名前に当たるものだけです（言い換えは見つけられません）。PR のレビューで見ます。
- **Claude Code の版と OS。** 拒否と `hooks` の書き方は、確かめた版（2026-11 時点の公式ドキュメント）に合わせています。古い版では、効かないことがあります。起動したら `/permissions` を打ち、拒否の一覧に `Edit(/src/core/**)` などが並ぶことを確かめます。台本と設定は、Mac でだけ動作を確かめました。Windows では、確かめていません。
