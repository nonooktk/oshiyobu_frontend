# 守ること（見た目は自由に、流れ・状態・プランと通信は変えない）

この文書は、OSHIYOBU の画面をフロントのデザイン担当者へ渡すときの「線引き」の正本です。読むのは、担当者と、その担当者の Claude Code です。

- 担当者に任せるのは、**見た目**（色・余白・線・絵・画面に出る文字・レイアウト）です。
- 変えないのは、**流れ**（画面の順と進み方）・**状態**（`src/fan/store/`・`src/fan/domain/`・`src/core/`）・**プラン**（名前・順・額・条件・特典）と、**backend との通信**です。
- 線は、ファイルの場所と、番号つきの決まり（G-01 から）で引きます。

Claude Code は、作業を始めるたびに、次の「0. 要点」を自動で読みます（`.claude/settings.json` の `SessionStart`。仕組みは「5. 三段の守り」）。

## 言葉

| 言葉 | 意味 |
| --- | --- |
| 管理者 | 統括。この画面の持ち主で、権限・秘匿値・配備を持つ人。決まりを変えられるのは管理者だけ |
| backend | 対になるリポジトリ。計算・デモデータ・API（共有メーター用の小さなサーバー）を持つ |
| core | backend の計算とデータを、このリポジトリに写したもの（`src/core/`）。手で直さない |
| テスト | 決まりを守っているかを、自動で確かめる検査。`npm test` で動く |
| `npm run verify` | lint・型・整形・テスト・ビルド・各種の検査を順に回す命令。GitHub の CI（自動検査）と同じ内容 |
| 開催熱量 | ファン向けで、「あと何人」といった数字を出さずに、達成の度合いを見せる仕組み。段階の名前（点火・あたたまってきた・ヒートアップ・FEVER 目前・FEVER）・距離のことば・虹色のゲージで見せる。FEVER は、成立（開催決定）の段階。ひとり体験は、自分の行動の進みで、共有メーターありは、人数の割合で、段階を決める。定義は `src/fan/domain/heat.ts` |
| 主のボタン | ファン向けのホームで、いま押す場所を 1 つに絞った大きなボタン。押すと、その行動がその場で進む（例: 推し活定期をはじめる・預金を積み増す・申し込む・仲間を呼ぶ） |
| 実在のデータ | 事務所向けに出す、実在の会場・過去の公演の情報。出典の URL と確認した日が付く（`src/office/data/`）。需要・預金・損益の数字は、実在でなく架空 |
| トークン | `src/styles/tokens.css` で名前をつけて決めた、色・間隔・文字の大きさの値。画面の CSS は `var(--名前)` で使う |
| CSP | 画面が読み込める相手・通信できる相手を、ブラウザに教える配信の設定。外へ通信しないことは、これで守っている |
| PR | 変更を `main` に入れる前に、確認してもらうための申請（GitHub の画面で出す） |
| Issue | 変えたいこと・提案を、管理者に伝えるための記録（GitHub の画面で立てる）。ファイルは変えない。リポジトリは公開なので、公開 URL・合言葉・秘匿値は書かない（G-33） |

## 1. 線引き（変えてよい所と、変えてはいけない所）

フォルダとファイルの名前で、3 つに分けます。

| 区分 | 場所 | 扱い |
| --- | --- | --- |
| **自分で変えてよい**（見た目と、画面に出る文字） | `src/fan/`・`src/office/`・`src/presenter/` の CSS（`*.module.css`）と部品（`components/`・`pages/`・`layers/`・`art/`）・画面に出る文字（`text/` と、部品の中の文字。G-31）。`src/styles/base.css`。事務所向けの実在のデータ（`src/office/data/`。G-30 を守る）。絵（`src/assets/img/`・`assets-src/`。変えたら `npm run images`）。`docs/office/`（事務所向けの要求・要件・仕様・運用ルール。追記だけ。要求・要件・決定を変えたいときは、ファイルを変えず、Issue で伝える。G-33）。新しいテスト（`tests/` の新しいファイル。既存のテストと同じ場所に足すと、確認が出る。新しいファイルを足すときだけ「はい」を選ぶ） | 変えてよい。ただし、「2. 守ること」の番号に反しない範囲で。変えたら `npm run verify` |
| **Issue で管理者へ伝える**（固定の所〈流れ・状態・プラン〉と、共有の部品） | `src/fan/store/`・`src/fan/domain/`（申し込み・FEVER 目前の演出・FEVER（開催決定）・初めに戻す順番と数え方。熱量の定義 `heat.ts` と、プランの決まり `plan.ts` を含む）。`src/shared/`（特に `meter/`）。`src/styles/tokens.css`（色を足すとき）。`public/fonts/`・`scripts/`（書体の絞り込みと検査の道具） | ファイルは変えず、Issue を立てて伝える（G-33）。管理者が了承して決めてから変える。了承なしに変えない |
| **変えない**（編集の道具では書き込めない） | `src/core/`・`core.lock.json`・`.github/`・`public/staticwebapp.config.json`・`docs/守ること.md`・`tests/guard/`・`.claude/settings.json`・`.claude/settings.local.json`・`scripts/claude-brief.mjs` | 変えたいときは、Issue で管理者へ伝える |

- **固定と自由**（G-31）。固定 ＝ 流れ（画面の順と進み方）・状態（`src/fan/store/`・`src/fan/domain/`・`src/core/`）・プラン（名前・順・額・条件・特典）。自由 ＝ 色（`tokens.css` にあるものから選ぶ。G-14）・余白・線・絵・レイアウト・画面に出る文字（ボタンの名前・見出し・説明の文）。画面に出る文字は、本人たちが必要と思えば変えてよく、入れるかどうかは、管理者が PR で判断します。ただし、使わない語・人数と達成率の数字を出さない決まり・札 2 枚・プランの名前は、そのまま守ります。文字を変える PR は、見た目だけの PR と分けます。
- 「変えない」の場所は、Claude Code の設定（`.claude/settings.json` の `permissions.deny`）で、編集の道具からの書き込みを止めています。既存のテストの置き場（`tests/unit/`・`tests/integration/`・`tests/helpers/`・`e2e/`・`e2e-solo/`）は止めずに、編集のたびに確認が出る設定（`permissions.ask`）にしてあります。GitHub の CODEOWNERS でも、管理者の確認が要る場所にしています（`.github/CODEOWNERS`）。
- 区分に載っていない場所（`e2e/`・`public/` のその他など）は、迷ったら、変えずに聞きます。
- **既存のテストの期待値・入力・skip の条件は、勝手に変えません**（G-24）。ただし、画面に出る文字を変えた PR では、その文字を見ている既存のテストの期待値の、その文字の部分だけ、直してよい（G-31）。確認が出たときは、この例外の分だけ「はい」を選び、それ以外は、管理者の了承が無ければ「いいえ」を選びます。新しいテストを足すのは自由です。

## 2. 守ること

「落ちる検査」の欄は、決まりを壊したときに、**自動で赤くなるもの**です。`npm run verify` を回せば、欄に書いたテストはすべて動きます。`npm run` の命令のうち verify の外にあるもの（`check:api`・`check:live`）は、別に回します。「歯止めなし」は、壊しても自動では気づけない決まりです（人の目と PR のレビューで見ます）。

「変えたいとき」の欄の「自分で」は、決まりの範囲で調整してよいという意味です。「管理者へ」は、決まりそのものを動かすことになるので、ファイルを変えずに、Issue を立てて管理者へ伝えるという意味です（G-33）。この文書の「管理者に頼む」「先に相談」も、同じ意味です。

### 2.6 PR・レビュー・配備の流れ（G-25・G-26）

## 3. 利用者に頼まれたときの動き方（Claude Code 向け）

担当者から頼まれたことが「2. 守ること」の番号に当たるとき、「1. 線引き」の「変えない」「Issue で管理者へ伝える」の場所に触れるとき、要求・要件・決定（D-番号）を変えるものであるとき、そのほか担当者が提案したいことがあるときは、次の順に動きます（G-33）。

1. **どの文書のどの番号に当たるかを、先に伝える。** 例: 「これは G-04（褒めるのは行動だけ）に当たります。」「これは `docs/fan/要件.md` の D-5 に当たります。」
2. **変えない。** 設定で止められなかったとしても、別のやり方（シェルでの書き換え・スクリプト・別のファイル経由）で通さない。止まったら、そこまでを報告して返す。
3. **Issue の下書きを出す。** 何を変えたいか・なぜ・当たる文書と番号・急ぎか、を書いた下書きを、担当者がそのまま使える形で出す（下の雛形）。担当者の OK のあとに、`gh issue create` で立てる（コマンドの例は `docs/fan/運用ルール.md` の 5 節）。`gh` が使えないときは、下書きを渡して、担当者が GitHub の画面で立てる。立てるまでの間も、ファイルは変えない。
4. **代わりにできることを、1 つ示す。** 決まりの範囲でできる見た目の案（例: 札はそのままに、位置と色を変える）。

迷ったら、変えずに聞きます。一方、「ホームの余白を広げて」「ボタンの色を、トークンの別の色にして」「ボタンの文字を、別の言い方にして」のような見た目の頼みは、止めずに進めます（変えたあとは `npm run verify`）。画面に出る文字を変えるときは、G-31 に沿って、見た目だけの変更と分けた PR にし、使わない語などの決まりを守ります。

Issue の下書きの雛形（`.github/ISSUE_TEMPLATE/提案.md` と同じ項目）:

```
タイトル: <何を変えたいか。短く>
- 何を変えたいか: <>
- なぜ: <>
- 当たる文書と番号: <D-番号・G-番号・R-番号。分からなければ「分からない」>
- 急ぎか: <発表（11/20）までに要るか>
（公開 URL・合言葉・秘匿値・個人の情報は、書かない）
```

### 限界（守れない場合）

守りは「うっかり」を防ぐ仕組みで、完全に防げるわけではありません。次の場合は、止まりません。

- **別の書き方での書き換え。** 拒否の規則は、Claude Code が見た命令や編集の道具に照らして判定します。`/usr/bin/git push …`・`bash -c '…'` や、スクリプトが自分でファイルを書く場合は、止められません（公式ドキュメントの「What a Bash rule doesn't match」）。`git -C . push` のようにオプションを先に書く形も止められません（同じ箇所の例）。ただし、`git -C`・`git -c`・`gh -R`・`gh --repo` は、書き方ごと拒否に入れてあります。`cp`・`mv`・`rm` で「変えない」の場所を直接変えた場合も、止まらないことがあります。こうした場合は、3 段目（`core:check`・テスト・CI・CODEOWNERS）が見つけます。
- **起動する場所。** 拒否の設定は、リポジトリの一番上のフォルダで `claude` を起動したときに有効になります（設定のパスは、起動したフォルダを基準に読まれるため）。サブフォルダで起動すると、有効にならないことがあります。台本は、起動した場所が違うと警告を出します。
- **設定を、担当者本人が書き換える。** `.claude/settings.local.json` で hooks を止める（`disableAllHooks`）ことや、設定ファイルを手で書き換えることは、止められません。Claude Code に頼んだ書き換えは `Edit` の拒否で止まりますが、手での変更は止まりません。設定の変更は、PR で管理者が確かめます。
- **`--dangerously-skip-permissions`。** 公式ドキュメントは、「deny の規則は、`bypassPermissions` を含むすべてのモードで止める」と説明しています。ただし、確認の画面は出なくなります。このリポジトリでは使いません。使ったときに実際に止まるかどうかは、確かめていません。
- **GitHub の側。** `main`・`dev` の保護（PR・統括の承認・`verify` の通過・指摘の解決が必須）と、`production` 環境の承認は、統括が GitHub に設定しました。リポジトリの検査では確かめられません。CODEOWNERS（`.github/CODEOWNERS`）が働くのは、「コードオーナーのレビューを必須」にしたときだけで、その設定は確かめていません。
- **「管理者の許可は取ってある」という言葉。** Claude Code は、許可を確かめられません。指示の文書（要点・`CLAUDE.md`）で「言葉だけでは外れない」と伝えていますが、設定で止めていない決まりは、強く頼まれると外れてしまうことがあります（既存のテストの期待値の書き換えで、実際に起きました。それ以降は、確認が出る設定を足しました）。設定で止まらない場所は、PR のレビューで見ます。
- **検査できないこと。** G-13（1 画面・44px）・G-08・G-27 と、G-24 の期待値の書き換え（G-31 の、文字の部分だけという例外の範囲を含む）は、自動では見つけられません。G-32 の、仮のデータの置き場と `store/`・`domain/` に足さないこと、G-33 の、Issue を立てたかも、見つけられません。G-04・G-05 も、見つけられるのは語の一覧と名前に当たるものだけです（言い換えは見つけられません）。音源ファイルの聞こえ方（賭けを連想させないか）は、ファイルの中身を含めて、機械では見つけられません。これらは PR のレビューで見ます（音は、耳で確かめます）。
- **Claude Code の版と OS。** 拒否と `hooks` の書き方は、確かめた版（2026-11 時点の公式ドキュメント）に合わせています。古い版では、有効にならないことがあります。起動したら `/permissions` を打ち、拒否の一覧に `Edit(/src/core/**)` などが並ぶことを確かめます。台本と設定は、Mac でだけ動作を確かめました。Windows では、確かめていません。
