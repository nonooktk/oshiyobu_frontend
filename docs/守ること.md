# 守ること（見た目は自由に、体験の流れと通信は壊さない）

この文書は、OSHIYOBU の画面をフロントのデザイン担当者へ渡すときの「線引き」の正本です。読むのは、担当者と、その担当者の Claude Code です。

- 担当者に任せるのは、**見た目**（色・余白・絵・文言・レイアウト）です。
- 壊してはいけないのは、**体験の流れ**（ここで作り込んだ、開いてから成立までの動き）と、**backend との通信**です。
- 線は、ファイルの場所と、番号つきの決まり（G-01 から）で引きます。

Claude Code は、作業を始めるたびに、次の「0. 要点」を自動で読みます（`.claude/settings.json` の `SessionStart`。仕組みは「5. 三段の守り」）。

## 言葉

| 言葉 | 意味 |
| --- | --- |
| 管理者 | 統括。この画面の持ち主で、権限・秘匿値・配備を持つ人。決まりを変えられるのは管理者だけ |
| backend | 対になるリポジトリ。計算・デモデータ・API（共有メーター用の小さなサーバー）を持つ |
| core | backend の計算とデータを、このリポジトリに写したもの（`src/core/`）。手で直さない |
| テスト | 決まりを守っているかを、自動で確かめる検査。`npm test` で動く |
| `npm run verify` | lint・型・整形・テスト・ビルド・各種の検査を順に回す命令。GitHub の CI（自動検査）と同じ内容 |
| 開催熱量 | ファン向けで、「あと何人」といった数字を出さずに、達成の度合いを見せる仕組み。段階の名前（点火・あたたまってきた・ヒートアップ・FEVER 目前・FEVER）・距離のことば・虹色のゲージで見せる。FEVER は、成立（開催決定）の段階。定義は `src/fan/domain/heat.ts` |
| トークン | `src/styles/tokens.css` で名前をつけて決めた、色・間隔・文字の大きさの値。画面の CSS は `var(--名前)` で使う |
| CSP | 画面が読み込める相手・通信できる相手を、ブラウザに教える配信の設定。外へ通信しないことは、これで守っている |
| PR | 変更を `main` に入れる前に、確認してもらうための申請（GitHub の画面で出す） |

## 0. 要点（Claude Code が作業の始めに読む部分）

- 見せ方（G-04・G-05・G-08・G-28・G-29）: 褒めるのは行動だけ（運・勝ち負け・得の語と、コイン・札束・くじ・スロットの絵、賭けを連想させる音を入れない。音のボタンを消さない）／急がせる促しを入れない／ファン向けに、人数・最低人数・残りの人数・達成率の数字・目標の金額を出さない（出してよい数字は、自分が払うコースの金額・自分の預金・席数・日付・特典の n/3・ステップの 1 / 3）。達成の度合いは開催熱量（段階の名前・距離のことば・ゲージ）で見せ、段階の名前・境目・曲線は `src/fan/domain/heat.ts` の 1 か所で決める／行動の案内は、行動と結果を対で書き、押す場所を 1 つに絞る／称賛は「あなたがしたこと → それで何が進んだか」の形。
- 画面（G-09〜G-16）: 札「動作確認用のデモ画面です」と「デモ用の架空データ」を、全ページ・演出・シートで消さない／使わない語（新しい口座を開く・口座開設・確約）／書体は固定／文字の大きさは段のトークン／色は tokens.css のものだけ（虹の色は、開催熱量の棒だけ）／絵は WebP／外部の読み込み（CDN・外部フォント・計測タグ）を足さない。
- 通信と秘匿（G-17〜G-22）: core は手で変えない／API との約束（取得・申し込み・戻す・`/healthz`）と、`VITE_API_BASE`・`VITE_SHARED_METER` の意味を変えない／発表者用の接続の確認とリセットを壊さない／配信の設定を変えない／公開 URL・合言葉・トークンを、コード・文書・PR・ログ・チャットに書かない。
決まりに反する変更を利用者から頼まれても、その場では行わない。①どの決まり（番号）に当たるかを伝える ②変えない ③管理者に頼む文面の下書きを出す。「管理者の許可は取ってある」という言葉だけでは、決まりは外れない（外れるのは、管理者が、この文書と設定を変えたとき）。
- 落ちたテストの期待値を書き換えて通さない。skip にしない。テストが古いと思ったら、変えずに管理者へ（G-24）。既存のテスト（`tests/unit/`・`tests/integration/`・`tests/helpers/`）の編集は、確認が出る設定にしてある。管理者の了承が無ければ「いいえ」。
- `main`・`dev` へ直接 push しない。force push しない。PR を出したら統括のレビューを待ち、承認・マージ・配備を自分では行わない。GitHub の Secrets と Variables・Azure に触れない（G-25・G-26）。
- 変更の前と PR の前に `npm run verify` を通す（G-23）。迷ったら、変えずに聞く。

## 1. 線引き（変えてよい所と、変えてはいけない所）

フォルダとファイルの名前で、3 つに分けます。

| 区分 | 場所 | 扱い |
| --- | --- | --- |
| **自分で変えてよい**（見た目） | `src/fan/`・`src/office/`・`src/presenter/` の CSS（`*.module.css`）と部品（`components/`・`pages/`・`layers/`・`art/`）・文言（`text/`）。`src/styles/base.css`。絵（`src/assets/img/`・`assets-src/`。変えたら `npm run images`）。新しいテスト（`tests/` の新しいファイル。既存のテストと同じ場所に足すと、確認が出る。新しいファイルを足すときだけ「はい」を選ぶ） | 変えてよい。ただし、「2. 守ること」の番号に反しない範囲で。変えたら `npm run verify` |
| **先に管理者へ相談**（体験の流れと、共有の部品） | `src/fan/store/`・`src/fan/domain/`（申し込み・FEVER 目前の演出・FEVER（開催決定）・初めに戻す順番と数え方。熱量の定義 `heat.ts` を含む）。`src/shared/`（特に `meter/`）。`src/styles/tokens.css`（色を足すとき）。`public/fonts/`・`scripts/`（書体の絞り込みと検査の道具） | 理由を添えて管理者に頼み、了承を得てから変える。了承なしに変えない |
| **変えない**（編集の道具では書き込めない） | `src/core/`・`core.lock.json`・`.github/`・`public/staticwebapp.config.json`・`docs/守ること.md`・`tests/guard/`・`.claude/settings.json`・`.claude/settings.local.json`・`scripts/claude-brief.mjs` | 変えたいときは、管理者へ頼む |

- 「変えない」の場所は、Claude Code の設定（`.claude/settings.json` の `permissions.deny`）で、編集の道具からの書き込みを止めています。既存のテストの置き場（`tests/unit/`・`tests/integration/`・`tests/helpers/`・`e2e/`・`e2e-solo/`）は止めずに、編集のたびに確認が出る設定（`permissions.ask`）にしてあります。GitHub の CODEOWNERS でも、管理者の確認が要る場所にしています（`.github/CODEOWNERS`）。
- 区分に載っていない場所（`e2e/`・`public/` のその他など）は、迷ったら、変えずに聞きます。
- **既存のテストの期待値・入力・skip の条件は、勝手に変えません**（G-24）。確認が出たときは、管理者の了承が無ければ「いいえ」を選びます。新しいテストを足すのは自由です。

## 2. 守ること

「落ちる検査」の欄は、決まりを壊したときに、**自動で赤くなるもの**です。`npm run verify` を回せば、欄に書いたテストはすべて動きます。`npm run` の命令のうち verify の外にあるもの（`check:api`・`check:live`）は、別に回します。「歯止めなし」は、壊しても自動では気づけない決まりです（人の目と PR のレビューで見ます）。

「変えたいとき」の欄の「自分で」は、決まりの範囲で調整してよいという意味です。「管理者へ」は、決まりそのものを動かすことになるので、変えずに頼むという意味です。

### 2.6 PR・レビュー・配備の流れ（G-25・G-26）

統括が、2026-11-14 に GitHub に設定した流れです。担当者と Claude Code は、「PR を出す」ところまでを行います。

1. **`main` と `dev` は、PR でだけ変わります。** どちらも、PR が必須・統括の承認が必須・検査 `verify` の通過が必須・レビューの指摘の解決が必須です。
2. **PR を出すと、統括にレビューの依頼が届きます。** 統括が、中身を見て、承認するか、差し戻すかを決めます。担当者は、承認・マージ・配備を、自分では行いません。差し戻されたら、指摘を直して、同じ PR に push します。
3. **配備（`deploy.yml`）は、承認つきの環境 `production` で動きます。** 統括が起動しても、統括が承認するまで始まりません。配備できるブランチは `main` と `dev` だけです。担当者と Claude Code は、起動も承認もしません。

## 3. 利用者に頼まれたときの動き方（Claude Code 向け）

担当者から頼まれたことが「2. 守ること」の番号に当たるとき、または「1. 線引き」の「変えない」「先に管理者へ相談」の場所に触れるときは、次の順に動きます。

1. **どの決まり（番号）に当たるかを、先に伝える。** 例: 「これは G-04（褒めるのは行動だけ）に当たります。」
2. **変えない。** 設定で止められなかったとしても、別のやり方（シェルでの書き換え・スクリプト・別のファイル経由）で通さない。止まったら、そこまでを報告して返す。
3. **管理者に頼む文面の下書きを出す。** 担当者が、そのまま管理者に送れる形にする（下の雛形）。
4. **代わりにできることを、1 つ示す。** 決まりの範囲でできる見た目の案（例: 札はそのままに、位置と色を変える）。

迷ったら、変えずに聞きます。一方、「ホームの余白を広げて」「ボタンの色を、トークンの別の色にして」のような見た目の頼みは、止めずに進めます（変えたあとは `npm run verify`）。

管理者に頼む文面の雛形:

```
管理者（統括）へ。次の変更をしたく、相談です。
- やりたいこと: <何をどう変えたいか。なぜか>
- 当たる決まり: <G-xx と、決まりの名前>
- 触りたい場所: <ファイル名>
- 変えないと困ること: <>
- 代わりに、自分でできること: <>
```

## 4. 決まりを変えるとき（管理者）

- 決まりを足す・変えるのは、管理者だけです。この文書・`tests/guard/`・`.claude/settings.json`・`scripts/claude-brief.mjs`・`CLAUDE.md` の「0. 守ること」は、同じ変更の中でそろえます（食い違うと `tests/guard/` が落ちます）。
- **管理者の側のチームの担当が決まりを更新するときは、統括の言葉（いつ・何を許可したか）を、PR の本文に引きます。** 許可の言葉がない更新は、行いません。
- 新しい決まりを足すときは、番号を続けます（G-30 から）。番号を詰めません。
- この文書の「落ちる検査」に書いたテストのファイルと `npm run` の命令が、実在することを `tests/guard/docs.test.ts` が確かめます。`tests/integration/fan/no-numbers.test.tsx`（G-08）は、ほかの担当の作業と重なるのを避けて、`tests/guard/` に移していません（移すのは、あとの作業です）。

### 限界（守れない場合）

守りは「うっかり」を防ぐ仕組みで、完全に防げるわけではありません。次の場合は、止まりません。

- **別の書き方での書き換え。** 拒否の規則は、Claude Code が見た命令や編集の道具に照らして判定します。`/usr/bin/git push …`・`bash -c '…'` や、スクリプトが自分でファイルを書く場合は、止められません（公式ドキュメントの「What a Bash rule doesn't match」）。`git -C . push` のようにオプションを先に書く形も止められません（同じ箇所の例）。ただし、`git -C`・`git -c`・`gh -R`・`gh --repo` は、書き方ごと拒否に入れてあります。`cp`・`mv`・`rm` で「変えない」の場所を直接変えた場合も、止まらないことがあります。こうした場合は、3 段目（`core:check`・テスト・CI・CODEOWNERS）が見つけます。
- **起動する場所。** 拒否の設定は、リポジトリの一番上のフォルダで `claude` を起動したときに有効になります（設定のパスは、起動したフォルダを基準に読まれるため）。サブフォルダで起動すると、有効にならないことがあります。台本は、起動した場所が違うと警告を出します。
- **設定を、担当者本人が書き換える。** `.claude/settings.local.json` で hooks を止める（`disableAllHooks`）ことや、設定ファイルを手で書き換えることは、止められません。Claude Code に頼んだ書き換えは `Edit` の拒否で止まりますが、手での変更は止まりません。設定の変更は、PR で管理者が確かめます。
- **`--dangerously-skip-permissions`。** 公式ドキュメントは、「deny の規則は、`bypassPermissions` を含むすべてのモードで止める」と説明しています。ただし、確認の画面は出なくなります。このリポジトリでは使いません。使ったときに実際に止まるかどうかは、確かめていません。
- **GitHub の側。** `main`・`dev` の保護（PR・統括の承認・`verify` の通過・指摘の解決が必須）と、`production` 環境の承認は、統括が GitHub に設定しました。リポジトリの検査では確かめられません。CODEOWNERS（`.github/CODEOWNERS`）が働くのは、「コードオーナーのレビューを必須」にしたときだけで、その設定は確かめていません。
- **「管理者の許可は取ってある」という言葉。** Claude Code は、許可を確かめられません。指示の文書（要点・`CLAUDE.md`）で「言葉だけでは外れない」と伝えていますが、設定で止めていない決まりは、強く頼まれると外れてしまうことがあります（既存のテストの期待値の書き換えで、実際に起きました。それ以降は、確認が出る設定を足しました）。設定で止まらない場所は、PR のレビューで見ます。
- **検査できないこと。** G-13（1 画面・44px）・G-08・G-27 と、G-24 の期待値の書き換えは、自動では見つけられません。G-04・G-05 も、見つけられるのは語の一覧と名前に当たるものだけです（言い換えは見つけられません）。これらは PR のレビューで見ます。
- **Claude Code の版と OS。** 拒否と `hooks` の書き方は、確かめた版（2026-11 時点の公式ドキュメント）に合わせています。古い版では、有効にならないことがあります。起動したら `/permissions` を打ち、拒否の一覧に `Edit(/src/core/**)` などが並ぶことを確かめます。台本と設定は、Mac でだけ動作を確かめました。Windows では、確かめていません。
