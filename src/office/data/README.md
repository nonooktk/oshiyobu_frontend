# src/office/data/（事務所向け専用のデータ置き場）

事務所向け（`/`）の画面に出す、**実在のデータ**（会場・過去の公演）を置く所です。決まりは `docs/守ること.md` の G-30 です。置き場と検査は管理者が用意しました。データは、事務所向けの担当者が足してかまいません（統括の決定）。

## 構成

| ファイル | 中身 |
| --- | --- |
| `types.ts` | 型。会場（`VenueRecord`）と過去の公演（`PastEvent`） |
| `venues.ts` | 会場の配列 `VENUE_RECORDS`。初めは空 |
| `events.ts` | 過去の公演の配列 `PAST_EVENTS`。初めは空 |
| `index.ts` | 読み込み先。画面の部品は、このファイルから読む |

このほかのファイル（`.json` や別の `.ts`）は、足しません。足したいときは、変えずに管理者へ頼みます（データの検査が届かなくなるため）。

## 入れてよいもの・いけないもの

| 入れてよいもの | 入れてはいけないもの |
| --- | --- |
| 会場の名前・市区・収容人数・種類（公開の情報） | 個人の情報（本名・メールアドレス・電話番号・SNS のアカウント） |
| 過去の公演の、芸名・団体名・日付（公開の告知にあるもの） | 需要・預金・費用・損益・見込みの数字（これらは架空のまま、core にある） |
| 1 件ごとの、出典の URL と、確認した日 | 出典のない行。出典を開けない行 |

## 足し方の決まり

1. **出典の URL は必須。** `https://` で始まる、誰でも開ける公開のページ（公式サイト・公式の告知・自治体・チケットの告知ページ）にします。
2. **確認した日は必須。** 自分が出典を開いて確かめた日を `YYYY-MM-DD` で書きます。ほかの人の日付を写しません。
3. **収容人数は、公式の値を優先します。** チケットサイトなど二次情報のときは、`capacityBasis` に、二次情報だと書きます。
4. **個人の情報を入れません。** 出演者は、公開の告知にある芸名・団体名だけです。
5. **計算に使いません。** 損益・判定・需要の計算は、core だけが行います。この置き場のデータを、`view.ts`・`scatter.ts`・`store.ts` や、core の計算の関数を呼ぶ部品に渡しません。`src/core/`・`src/fan/` は、この置き場を読みません。
6. **画面では、実在のデータと、架空の数字の区別が分かるようにします。** 実在のデータには、出典と確認日を添えます。需要・預金・損益は、これまでどおり「デモ用の架空データ」です。
7. 出典を開けなくなった・値が違っていた行は、その行を外します。
8. **漢字は、フォントに足しません**（統括の決定 2026-11-14。実在の名前は字の種類が多く、フォントの量の上限を超えるため）。この置き場の字は、フォントの字の漏れの検査（`tests/unit/fonts.test.ts`）と、フォントの絞り直し（`npm run fonts:build`）の対象から外してあります（`scripts/fonts-lib.mjs` の `FONT_EXCLUDED_DIRS`）。MOBO に無い字は、事務所向けの書体の並び（`--font`）のうしろにある、端末の書体で出ます。珍しい字を入れても、`npm run verify` は落ちません。ただし、データの字を、置き場の外（事務所向けの部品・CSS）に書き写すと、そちらは、これまでどおり検査されます（検査を避けるための書き写しは、しません）

## 例（形だけ。実際の値ではありません）

```ts
export const VENUE_RECORDS: readonly VenueRecord[] = [
  {
    id: '<会場の ID>',
    name: '<会場の名前>',
    pref: '<県の名前>',
    city: '<市区>',
    capacity: <収容人数>,
    capacityBasis: '<公式の値、または二次情報の名前>',
    type: '<会場の種類>',
    sourceUrl: 'https://<出典のページ>',
    checkedOn: '<YYYY-MM-DD>',
  },
];
```

## 検査

`tests/guard/office-data.test.ts` が、`npm run verify` の中で、次を確かめます。落ちたときは、番号と「管理者へ」の案内が出ます。

- 全部の行に、`https://` で始まる出典の URL と、`YYYY-MM-DD` の確認日がある。公演の会場が、会場の配列にある
- メールアドレス・電話番号の形の文字が無い
- この置き場のファイルが、上の表の 4 つと、この README.md だけである
- `src/core/`・`src/fan/` などが、この置き場を読んでいない。`view.ts`・`scatter.ts`・`store.ts` が読んでいない。この置き場を読む部品が、core の計算の関数を呼んでいない

データが空のときも、検査は通ります。

フォントの検査が、この置き場を見ていないことは、`tests/unit/fonts-office-data.test.ts` が確かめます（置き場に、一覧に無い字を入れても漏れに出ない。置き場の外に入れたら、これまでどおり漏れに出る）。
